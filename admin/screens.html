Admin portal — coded mockups

Interactive mockups of the SheDrive admin portal, built on the production front-end stack. Data is mock but behaviour is real: filters, sorting, pagination and account actions all work. Desktop-first and English-only, per the agreed admin UX rules.

How to review these

  • No sign-in needed. Every internal screen opens directly — click any card below and you land on that screen. The same is true of the links inside the ADO design stories.
  • The sign-in screen is itself a design screen, so it is still here to review. It works end to end with ops.lead@shedrive.app / shedrive2026, then the 2FA code 123456.
  • To see the production behaviour where an unauthenticated visitor is bounced to sign-in, add ?auth=strict to any screen URL after signing out.
  • Every list screen accepts a forced state in the URL — ?state=empty, ?state=loading, ?state=error, ?state=long. The chips below link straight to them.
  • ?state=long stretches names and addresses to test overflow, including long Arabic-transliterated names in an English grid.
  • Maps use Mapbox because it is already wired into this repo. Stories #1823–#1826, #1756 and #1831 specify the Google Maps JavaScript API — that discrepancy is open and needs a decision.
  • Nothing here talks to a backend. Actions mutate in-memory data, so a full page reload resets everything to the seed state.

Screen-to-story mapping and open questions are tracked in docs/ux/admin-wireframes.md. Component APIs are documented in docs/ux/admin-component-contract.md.
